  - 将来的なエンドクライアント向け協業プランに落とし込めること

## 2. Be-Links社の仮説プロファイリング（初回提案版）
> ※公開情報の精査前の「ヒアリング前提仮説」。初回打合せで補正する。

### 2-1. 組織特性（仮説）
- 意思決定が速く、外部連携に前向き
- 少人数でも高密度に実行する文化
- 研修に対して「理論」より「実装・運用」重視

### 2-2. AI導入成熟度（仮説）
- 生成AIの基本利用は開始済み
- ただし、
  - プロンプトの属人化
  - ワークフロー統合不足
  - セキュリティ/運用ルール未整備
  がボトルネックになりやすい段階

### 2-3. 事業上のニーズ（仮説）
- 社内生産性向上（提案作成、調査、要約、ドキュメント整備）
- ナレッジ資産化（社内資料/議事録/提案書の再利用）
- クライアント支援メニューへの転用（内製→外販）

## 3. 研修設計方針
1. **ツール比較ではなく「業務フロー設計」を主軸**にする
2. 2時間内で「理解」より**1つの実装雛形を完成**させる
3. 研修後7日で回るよう、**運用テンプレート**まで提供する

## 4. 推奨研修メニュー（2時間・実装重視）

### Module A（15分）AIエージェント実装の全体像
- エージェントを「目的・データ・判断・実行・評価」の5層で分解
- 失敗しやすい設計（目的不明/評価軸なし/人間承認なし）を先に共有

**成果物**
- 自社業務1件のエージェント化キャンバス

### Module B（35分）ChatGPT / Gemini / NotebookLM 役割分担
- ChatGPT：要件整理、タスク分解、ワークフロー草案
- Gemini：マルチモーダル要約、Google Workspace連携想定
- NotebookLM：社内資料からの根拠付きQA、情報ソース統合

**成果物**
- 3ツール使い分けマトリクス（業務別）

### Module C（45分）ハンズオン：最小AIエージェントを作る
テーマ例：
- 「問い合わせ一次対応ドラフト作成エージェント」
- 「提案書下書き＋根拠資料抽出エージェント」

実装ステップ：
1. 入力定義（何を受け取るか）
2. 推論手順（何をどう考えさせるか）
3. 出力規格（テンプレ化）
4. 人間レビュー点（承認フロー）
5. ログ/改善観点（再学習ではなく改善運用）

**成果物**
- 明日から使える運用プロンプトセット
- レビュー観点チェックリスト

### Module D（25分）導入計画と協業プラン化
- 30日導入ロードマップ（PoC → 定着 → 横展開）
- KPI例：時間削減率、初稿作成速度、再利用率
- エンドクライアント向け商品化の骨子（研修→伴走→実装支援）

**成果物**
- 30日アクションプラン
- 協業メニュー叩き台
